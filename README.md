# Сервис генерации документов

Веб-сервис для выпуска печатных форм: загружаете шаблон в docx, заполняете форму — получаете готовый PDF и docx. Документы выпускаются от имени разных организаций, реквизиты подставляются автоматически.

## Что умеет

| Требование | Реализация |
|---|---|
| Генерация печатных форм в PDF | Подстановка данных в docx через PhpWord, конвертация в PDF через LibreOffice (Gotenberg) |
| Загрузка docx-шаблонов и их редакция | Загрузка перетаскиванием, версионирование файла с возможностью отката, настройка полей формы |
| Скачивание печатных форм | Скачивание PDF и docx, журнал документов с повторным скачиванием |
| Документы для разных организаций | Справочник организаций с реквизитами, шаблоны общие или привязанные к организации |

## Запуск

```bash
docker compose up -d --build
```

Приложение: **http://localhost:8080**

Больше ничего устанавливать не нужно: PHP, Composer, Node и LibreOffice работают внутри контейнеров. При первом запуске автоматически создаётся база, применяются миграции и загружаются демонстрационные данные — две организации и три готовых шаблона (счёт, акт, договор). Сервис можно попробовать сразу.

Остановка:

```bash
docker compose down
```

## Как это работает

### Метки в шаблоне

В docx-файле в нужных местах пишутся метки. Сервис сам находит их при загрузке и строит из них форму заполнения.

| Метка | Кто заполняет |
|---|---|
| `${org.name}`, `${org.inn}`, `${org.bank_account}`, `${org.director_name}` … | Сервис — из реквизитов выбранной организации |
| `${doc.number}`, `${doc.date}` | Сервис — из номера и даты документа |
| `${client_name}`, `${total_amount}` и любые другие | Пользователь в форме генерации |

Полный список меток организации соответствует полям её карточки: `full_name`, `inn`, `kpp`, `ogrn`, `legal_address`, `actual_address`, `phone`, `email`, `bank_name`, `bank_account`, `bank_corr_account`, `bank_bik`, `director_name`, `director_position`.

### Порядок работы

1. **Организации** — заводятся реквизиты: ИНН, КПП, банк, подписант, логотип.
2. **Шаблоны** — загружается docx. Сервис находит метки и создаёт поля формы, угадывая их типы по названию (`*_date` → дата, `*_amount` → число, `*_address` → многострочный текст).
3. **Карточка шаблона** — правятся подписи полей, типы, обязательность и значения по умолчанию. Здесь же загружается новая версия файла и хранится вся история.
4. **Генерация** — выбирается организация и шаблон, заполняется форма, доступен предпросмотр PDF без сохранения.
5. **Документы** — журнал выпущенных форм с повторным скачиванием PDF и docx.

### Модель данных

- `organizations` — реквизиты организаций.
- `templates` — карточка шаблона, ссылка на актуальную версию.
- `template_versions` — файлы docx с найденными метками. Старые версии не удаляются.
- `template_fields` — настройка полей формы: подпись, тип, обязательность.
- `documents` — журнал: шаблон, **версия шаблона**, организация, введённые данные, пути к файлам.

Документ ссылается именно на версию шаблона, по которой был создан: если шаблон потом изменят, ранее выпущенные документы останутся такими, какими были.

## Принятые решения

**Конвертация через Gotenberg, а не PHP-библиотекой.** Библиотеки вроде dompdf собирают PDF заново и ломают вёрстку печатных форм. Gotenberg использует настоящий LibreOffice, поэтому шрифты, таблицы и колонтитулы сохраняются. Отдельный контейнер также держит PHP-образ лёгким и позволяет заменить конвертер, не трогая код приложения.

**Поиск меток через PhpWord, а не регулярным выражением.** Word нередко разрывает метку на части внутри XML, если внутри неё менялось форматирование. `TemplateProcessor` такие разрывы склеивает — поиск по тексту их бы пропустил.

**Собственное правило проверки файла.** Стандартное `mimes:docx` определяет тип по содержимому, а системная библиотека распознаёт docx то как `application/zip`, то как `application/octet-stream` — в контейнере загрузка ломалась бы. Правило `DocxFile` заглядывает внутрь архива и проверяет наличие `word/document.xml`: обойти переименованием нельзя, работает одинаково везде.

**Версионирование вместо перезаписи.** «Редакция шаблона» — это замена файла и настройка полей. При замене настройки полей сохраняются, новые метки добавляются, исчезнувшие удаляются, а старый файл остаётся в истории.

**Экранирование значений.** Символы `&`, `<`, `>` в данных ломают XML внутри docx, и Word отказывается открывать файл. Значения экранируются, переносы строк превращаются в переносы Word.

## API

```
GET    /api/health                                    состояние сервиса и конвертера

GET    /api/organizations                             список
POST   /api/organizations                             создание (multipart для логотипа)
GET    /api/organizations/{id}
PUT    /api/organizations/{id}
DELETE /api/organizations/{id}

GET    /api/templates?organization_id=                список (общие + организации)
POST   /api/templates                                 загрузка шаблона (multipart)
GET    /api/templates/{id}                            карточка: версии, поля, метки
PUT    /api/templates/{id}
DELETE /api/templates/{id}

POST   /api/templates/{id}/versions                   новая версия файла
GET    /api/templates/{id}/versions/{v}/download      скачать исходный docx
POST   /api/templates/{id}/versions/{v}/restore       вернуть версию как актуальную

GET    /api/templates/{id}/fields                     настройки полей
PUT    /api/templates/{id}/fields

GET    /api/documents?organization_id=&template_id=   журнал
POST   /api/documents                                 генерация
POST   /api/documents/preview                         предпросмотр PDF без сохранения
GET    /api/documents/{id}/download?format=pdf|docx   скачивание
DELETE /api/documents/{id}
```

## Тесты

```bash
docker compose exec app php artisan test
```

17 тестов покрывают разбор меток, загрузку шаблонов и версионирование, подстановку реквизитов, форматирование дат и чисел, экранирование спецсимволов, валидацию и скачивание файлов. Конвертер в тестах подменяется заглушкой, поэтому они не зависят от контейнера Gotenberg.
